# Design
## Source of truth
Active · 2026-11-07 · `/coding` only. Evidence: static/coding.html, coding.css, coding.js, tests/test_coding_practice.py and request for reduced-distraction study. Other application screens retain their own layouts. External evidence: [W3C focus guidance](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o5-user-focus/), [task expectations](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o5p04-task-expectations/), [adjustable timing](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html).
## Brand
Calm, practical, respectful. Trust through saved drafts and clear next actions. Avoid clinical efficacy claims, streak pressure, flashing rewards and punitive timeouts.
## Product goals
Reduce the effort of starting and returning to Java practice. The current scene and audio action must fit in the first viewport at 1440×900 and 390×844; supporting transcript can continue below. Show one problem and one immediate step. Preserve all 30 problems, Java downloads, records and backups.
## Personas and jobs
A developer preparing for an observed coding interview in two days. Needs small actionable steps, fewer distractions and easy interruption recovery. Preferences vary; controls remain optional.
## Information architecture
Default view is a narrated, code-rendered slide lesson. Each of 30 problems has five scenes with authored algorithm diagrams, a Java snippet, and Korean prerecorded audio. Every scene has sentence-cued keyframes: stable data objects move between positions, edges expose relationships, and values/selection change with the actual example. A media-clock-driven renderer interpolates moves; pause and seeking freeze or restore the exact visual state. A scene scrubber supports replaying the reasoning. User starts sound explicitly; ending narration advances only when automatic progression is enabled. Practice remains accessible as a separate mode with compact current task, 3-step navigation, active work panel. Expandable full curriculum contains counts and filters. Read → implement → explain/test; steps are freely navigable. Break screen pauses work and offers explicit resume.
## Design principles
Progressive disclosure, one prominent next action, persistent context, no forced task changes. Narrated slides advance only through the existing explicit automatic-next preference. Short sessions are adjustable design defaults, not prescribed clinical intervals.
## Visual language
Use a restrained white / cool-gray / blue palette, with semantic CSS variables for text, secondary text, background, stroke and action. Blue is concentrated on the current data item and primary playback action. Remove marketing hero copy and nested card borders. Single-column 760px reading width, 16px body, clearly differentiated title/scene/caption hierarchy. Source references: [Toss color roles](https://toss.tech/article/tds-color-system-update) and [functional UX writing](https://toss.im/tossfeed/article/uxwriter-interview); this is an original study interface, not a claim to reproduce proprietary TDS tokens. No unsolicited sounds or animated celebration. Korean narration is explicitly requested through playback controls; pause/repeat/rate, synchronized sentence subtitles on by default, and a full scene transcript are provided. Subtitle timing follows the media clock using measured sentence audio boundaries; no character-count estimates. A visible subtitle toggle persists and the static summary returns when captions are off. Caption space is reserved to reduce layout jumps; captions do not use aria-live, avoiding double speech. Visible keyboard focus.
## Components
Flat lesson header, one pale-gray animation stage, five quiet scene segments, a scene timeline, actual MP3 audio and one primary playback action. Arrays, stacks, queues, graphs, grids, intervals and caches have distinct spatial layouts authored against the narrated example, rather than shared bullet-list reveals. Secondary playback options live in a native disclosure. Persistent opt-in quiet view hides navigation and mode switching; its exit button and errors always remain available. Escape exits quiet view; Space controls audio only outside interactive fields. Focus toolbar, native details curriculum drawer, step buttons with aria-current, 5/10/15 minute focus selector, hideable timer, break/resume panel, next-action note. Existing editor and help remain.
## Accessibility
Target WCAG 2.2 AA. Native buttons and labels; keyboard controls; no second-by-second live announcements. Reduced motion switches immediately between the same meaningful diagram states without interpolated travel; no decorative looping or camera shake. Animation and subtitles derive from audio.currentTime rather than independent timers. Hidden panels cannot receive keyboard focus. No forced countdown, auto-submit or lost work at expiry.
## Responsive behavior
Single column by default; 390px mobile without horizontal overflow. Buttons wrap, code scrolls internally, touch targets at least 44px.
## Interaction states
Loading states disable unavailable controls. Normal status text is concise; errors remain visible and actionable even in quiet view. Errors keep saved work. Timer is opt-in, pauses on break and problem changes, survives reload. Break persists on reload and does not automatically resume. Completion remains self-assessed; assisted work stays in review. Lesson progress never marks a problem independently solved. Switching problem/mode or hiding the browser pauses narration. Audio failure displays an explicit error and never silently advances. Returning restores scene position without autoplay.
## Content voice
Short Korean instructions. Say '여기서 이어가면 됩니다', not failure or guilt. Distinguish session timer from problem recommendation duration. Avoid diagnostic labels on screen.
## Implementation constraints
Vanilla JS/CSS, no dependencies, no SQLite mutations. Preserve Java storage key and Python archive. New optional state fields validate and default for old backups. Browser tests cover steps, timer, break, restoration, existing Java downloads, real audio playback and slide/audio synchronization. Narration build uses local macOS say (Yuna) and FFmpeg; playback works from committed MP3 assets without those tools. No MP4 video is generated.
