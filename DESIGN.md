# Design
## Source of truth
Active · 2026-11-07 · `/coding` only. Evidence: static/coding.html, coding.css, coding.js, tests/test_coding_practice.py and request for reduced-distraction study. Other application screens retain their own layouts. External evidence: [W3C focus guidance](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o5-user-focus/), [task expectations](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o5p04-task-expectations/), [adjustable timing](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html).
## Brand
Calm, practical, respectful. Trust through saved drafts and clear next actions. Avoid clinical efficacy claims, streak pressure, flashing rewards and punitive timeouts.
## Product goals
Reduce the effort of starting and returning to Java practice. The current scene and audio action must fit in the first viewport at 1440×900 and 390×844; supporting transcript can continue below. Show one problem and one immediate step. Preserve all 30 problems, Java downloads, records and backups.
## Personas and jobs
A developer preparing for an observed coding interview in two days. Needs small actionable steps, fewer distractions and easy interruption recovery. Preferences vary; controls remain optional.
## Information architecture
Default view is a narrated, code-rendered slide lesson. Each of 30 problems has five scenes with authored algorithm diagrams, a sentence-linked Java code companion, and Korean prerecorded audio. Each subtitle cue links to reviewed 1-based lines in the canonical Java solution, with a short role explanation. Highlighted excerpts appear after the problem introduction in lesson mode; expanding the full source highlights the same lines and follows them inside the code pane without scrolling the page. These are explanation references, not a runtime debugger. Code exposure counts as assistance. Every scene has sentence-cued keyframes: stable data objects move between positions, edges expose relationships, and values/selection change with the actual example. A media-clock-driven renderer interpolates moves; pause and seeking freeze or restore the exact visual state. A scene scrubber supports replaying the reasoning. User starts sound explicitly; ending narration advances only when automatic progression is enabled. Practice remains accessible as a separate mode with compact current task, 3-step navigation, active work panel. Expandable full curriculum contains counts and filters. Read → implement → explain/test; steps are freely navigable. Break screen pauses work and offers explicit resume.
## Design principles
Progressive disclosure, one prominent next action, persistent context, no forced task changes. Narrated slides advance only through the existing explicit automatic-next preference. Short sessions are adjustable design defaults, not prescribed clinical intervals.
## Visual language
Use a warm off-white / sage-gray / deep teal palette, with semantic CSS variables for text, secondary text, background, stroke and action. Deep teal is concentrated on the current data item and primary playback action. Remove marketing hero copy and nested card borders. A 760px reading width by default, expanding to a 1200px two-column lesson workspace at 1100px and above, 16px body, clearly differentiated title/scene/caption hierarchy. Source references: [Toss color roles](https://toss.tech/article/tds-color-system-update) and [functional UX writing](https://toss.im/tossfeed/article/uxwriter-interview); this is an original study interface, not a claim to reproduce proprietary TDS tokens. No animated celebration. User-requested BGM is an original, sparse electric-piano/pad instrumental without vocals or percussion, played quietly with narration and stopped on pause/tab change. Subtitle and introductory prose use a short media-clock typewriter reveal (complete within 1.2 seconds); reserve the full text layout, do not animate code or data values, and provide an off toggle. Korean narration is explicitly requested through playback controls; pause/repeat/rate, synchronized sentence subtitles on by default, and a full scene transcript are provided. Subtitle timing follows the media clock using measured sentence audio boundaries; no character-count estimates. A visible subtitle toggle persists and the static summary returns when captions are off. Caption space is reserved to reduce layout jumps; captions do not use aria-live, avoiding double speech. Visible keyboard focus.
## Components
Flat lesson header, one pale-gray animation stage, five quiet scene segments, a scene timeline, actual MP3 audio and one primary playback action. Arrays, stacks, queues, graphs, grids, intervals and caches use shared, deterministic layout components with separate annotation lanes. Preserve authored values, FIFO/order, IDs, edges and cue times. Check node bounds and collisions in all frames and sampled transitions; use fade/reposition when movement would cross other objects. Secondary playback options live in a native disclosure. Persistent opt-in quiet view hides navigation and mode switching; its exit button and errors always remain available. Escape exits quiet view; Space controls audio only outside interactive fields. Focus toolbar, native details curriculum drawer, step buttons with aria-current, 5/10/15 minute focus selector, hideable timer, break/resume panel, next-action note. Existing editor and help remain.
## Accessibility
Target WCAG 2.2 AA. Native buttons and labels; keyboard controls; no second-by-second live announcements. Reduced motion also disables typing. Reduced motion switches immediately between the same meaningful diagram states without interpolated travel; no decorative looping or camera shake. Animation and subtitles derive from audio.currentTime rather than independent timers. Hidden panels cannot receive keyboard focus. No forced countdown, auto-submit or lost work at expiry.
## Responsive behavior
At desktop widths the code companion sits beside the animation; on mobile it follows playback controls. Long source lines wrap within their original numbered row. Single column by default; 390px mobile without horizontal overflow. Buttons wrap, code scrolls internally, touch targets at least 44px.
## Interaction states
Loading states disable unavailable controls. Normal status text is concise; errors remain visible and actionable even in quiet view. Errors keep saved work. Timer is opt-in, pauses on break and problem changes, survives reload. Break persists on reload and does not automatically resume. Completion remains self-assessed; assisted work stays in review. Lesson progress never marks a problem independently solved. Switching problem/mode or hiding the browser pauses narration. Audio failure displays an explicit error and never silently advances. Returning restores scene position without autoplay.
## Content voice
Short Korean instructions. Explain the current object and why the next operation is needed. Display example numbers, letters and code identifiers literally (4, b, HashSet); keep a separately authored natural spoken reading per subtitle segment. Preserve cue event order when refining explanations so the diagram remains synchronized. Say '여기서 이어가면 됩니다', not failure or guilt. Distinguish session timer from problem recommendation duration. Avoid diagnostic labels on screen.
## Implementation constraints
Vanilla JS/CSS, no dependencies, no SQLite mutations. Preserve Java storage key and Python archive. New optional state fields validate and default for old backups. Browser tests cover steps, timer, break, restoration, existing Java downloads, real audio playback and slide/audio synchronization. Narration build uses local macOS say (Yuna) and FFmpeg; playback works from committed MP3 assets without those tools. No MP4 video is generated.

### 연속 강의와 공통 효과
- 자동 재생은 다음 장면과 다음 문제의 소개까지 이어지며 30번에서 종료한다.
- 플레이어 아래 문제 처음부터 보기 버튼은 소개부터 즉시 재생한다. 전체 Java 코드는 문제를 열 때 기본 펼침이다.
- 장면 페이드, 코드 강조 전환, 데이터 카드 색 전환과 활성 테두리는 공통 렌더러/CSS에서 적용한다. 위치·크기를 추가로 움직이지 않으며 동작 줄이기를 존중한다.

### 문제 시작 그림과 제목
- 30문제 모두 첫 음성 구간은 문제 번호와 문제명이다. 제목과 문제 소개 구간에는 문제별 ImageGen 그림을 공통 이미지 컴포넌트로 유지하고, 풀이 설명이 시작되면 자료구조 애니메이션으로 이어진다.
- 그림은 아이보리 바탕의 평면 2D 도식으로, 실제 예제의 숫자·배열·방향 화살표로 입력과 결과를 직접 표현한다. 3D 재질·그림자·장식 소품을 사용하지 않는다. 선택 항목은 딥그린, 제외 항목은 절제된 코럴로 구분한다. 이미지 로딩 실패 시 기존 제목 애니메이션을 유지한다.
- `/static/coding-images.html`에서 30문제를 모아 보고 원본 크기로 열 수 있다.
