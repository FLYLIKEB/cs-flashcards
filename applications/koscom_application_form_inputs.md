- `전공`, `전공기초`, `교양` 등 과목유형은 학사시스템의 실제 이수구분과 일치시킨다.

### 2. 입사 후 수행하고 싶은 업무와 준비

- 희망업무: 금융 소프트웨어 개발·운용, 시장·금융데이터 처리 시스템

- 증거: 92개 API, 10개 모듈, 약 400개 테이블, DB·Redis 무중단 이관
- 준비: Java·Spring, SQL, Redis, 배치·메시지 큐, 전역 로깅, 배포 전 검증
- 입사 후 방향: 금융업무와 데이터 정의를 먼저 익히고 성능·정확성·추적성을 함께 관리

### 3. 가장 관심 있게 수강한 교육사항

학교 과목 대신 **우아한테크코스 4기 Backend**를 사용한다. 문항이 학교교육 외 직업교육과 기타교육을 허용하므로 낮은 학교 성적을 다시 강조하지 않으면서 실제 학습과 성과를 설명할 수 있다.

- 구분: 직업교육
- 기간: 2022.02~2022.11
- 학습내용: Java·Spring 기반 서버 개발, 객체지향 설계, 웹 애플리케이션, 테스트, 리팩토링, HTTP 발표, 팀 프로젝트
- 관심 이유: 이론을 구현·리뷰·운영 가능한 결과물로 바꾸는 학습 방식
- 활용사례: 팀 프로젝트에서 BatchSize와 Fetch Join을 개선해 쿼리 수를 5,000개에서 6개로 감소
- 코스콤 연결: 다수 사용자가 이용하는 금융서비스에서 데이터 조회 성능과 안정성을 검증하는 개발자
- 제출 전 확인: 교육시간·회차·수료일은 수료증 또는 고용24 훈련이력과 대조

### 4. 팀워크 노하우와 갈등 해결

- 대표 소재: 최소주문금액 안내 기능
- 갈등: 기획은 일정과 고객경험, 개발은 안정성, 일부 유관부서는 단기 효과를 중시
- 본인 노하우: 각자의 주장을 반복하지 않고 사용자 행동지표와 공통 판단 기준으로 쟁점을 구조화
- 행동: 주문 가능 여부와 부족 금액을 보여주는 핵심 기능부터 작게 출시하도록 제안하고 상태·예외조건을 점검
- 결과: 합의를 이끌고 기능을 출시해 고객경험 개선에 기여
- 제출 전 확인: `7개 이상의 유관부서`와 `7개 팀` 중 실제 조직 단위로 통일하고, 수치가 없는 전환율 개선은 단정하지 않는다.

### 5. 차별화된 강점과 보완할 약점

- 강점: 국문학·디자인·컴퓨터공학을 함께 공부하고 백엔드 실무를 수행해 기술과 현업의 언어를 연결하는 문제 구조화 역량
- 강점 사례: 다부서 요구를 사용자 흐름과 시스템 상태로 정리하고 백엔드 기능으로 구현
- 약점: 정확히 설명하려다 초기 공유가 늦어지는 경향
- 보완 행동: 핵심 쟁점과 잠정 판단을 먼저 공유하고 상세 분석과 근거를 단계적으로 추가
- 주의: 전공명은 학적증명서의 공식 명칭과 일치시키고, 자기소개서에서는 학교명을 쓰지 않는다.
