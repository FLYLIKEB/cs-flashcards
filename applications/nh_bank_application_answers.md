## 경험기술서 1. 신규 서버 분리·대규모 이관

- 해당기관: 이용자 100만 명 이상 커머스 플랫폼의 사내 서비스개발 조직
- 본인기여도: 제출 전 실제 비율 확인
- 근무기간: 2023.12~2024.11

### 수행역할(담당업무)

**글자 수: 183자 / 300자 이내**

신규 상품 전시 서버 구축과 통합 시스템 개발을 담당했습니다. 92개 API, 10개 모듈, 약 400개 테이블의 의존관계를 정리하고 Spring 다중 데이터소스를 구성했습니다. API 마이그레이션과 DB·Redis 이관을 수행했으며, 약 1,000개 클래스의 사용 중단 참조를 자동 탐지하고 일괄 수정하는 도구를 개발했습니다.

### 주요성과

**글자 수: 167자 / 300자 이내**

상품·기획전 기능을 운영 중단 없이 신규 서버로 전환했습니다. 대량 변경을 자동화해 누락 위험을 낮추고 담당자가 예외 검토에 집중하도록 했습니다. 변경 전후 참조와 빌드 결과, 데이터 흐름을 단계별로 검증해 서비스 연속성을 지켰으며 장애 원인과 변경 영향을 추적할 수 있는 운영 기반을 강화했습니다.

### 적용 역량/기술

**글자 수: 166자 / 300자 이내**

Java, Spring Boot, JPA, MySQL, Redis, 다중 데이터소스, API·DB 마이그레이션을 활용했습니다. 복잡한 의존관계를 작은 전환 단위로 나누는 기획력, 데이터 무결성과 영향 범위를 확인하는 검증 역량, 반복 작업의 공통 규칙과 예외를 분리하는 자동화 역량을 적용했습니다.

## 경험기술서 2. 상품 전시 시스템 성능·운영 개선

- 해당기관: 이용자 100만 명 이상 커머스 플랫폼의 사내 서비스개발 조직
- 본인기여도: 제출 전 실제 비율 확인
- 근무기간: 2023.01~2024.11

### 수행역할(담당업무)

**글자 수: 163자 / 300자 이내**

상품 카탈로그·기획전·구좌·할인·필터·탭 등 전시 도메인의 백엔드 개발과 운영을 담당했습니다. 로그와 성능지표로 병목을 좁혀 DB 조회 순서와 캐시 구조를 개선했습니다. 또한 SQL 진입점 로깅과 MDC 기반 전역 로깅을 적용해 Batch·메시지 큐·JDBC·비동기 처리 흐름을 추적했습니다.

**글자 수: 175자 / 300자 이내**

TPS 1,000 환경의 배너 API 응답시간을 909ms에서 18ms로 줄여 약 98% 개선했습니다. 슬로우 쿼리 탐지 체계도 개선해 평균 원인 파악시간을 25분에서 9분으로 단축했습니다. 기능 배포에 그치지 않고 운영 지표와 로그로 결과를 확인해 고트래픽 상황의 고객 대기와 장애 대응 시간을 함께 줄였습니다.

### 적용 역량/기술

**글자 수: 193자 / 300자 이내**

Java, Spring Boot, JPA, QueryDSL, MySQL, Redis, Batch, 메시지 큐, JDBC, 비동기 처리와 MDC를 활용했습니다. 추측보다 같은 조건의 변경 전후 지표로 원인을 검증하는 데이터 기반 문제해결, 장애 흐름을 설명 가능한 기록으로 남기는 관측가능성, 고객 영향을 끝까지 확인하는 운영 역량을 적용했습니다.

## 경험기술서 3. 익명 커뮤니티 팀 프로젝트

### 수행역할(담당업무)

**글자 수: 193자 / 300자 이내**

백엔드 개발자 5명 중 1명으로 익명 커뮤니티 서비스를 개발했습니다. Java 11, Spring Boot, JPA, Hibernate, QueryDSL, MySQL, Jenkins를 활용해 서버 기능을 구현하고 코드리뷰에 참여했습니다. 운영 과정에서 과도하게 발생하는 조회 쿼리를 확인하고 BatchSize와 Fetch Join을 조정했습니다.

**글자 수: 192자 / 300자 이내**

실사용자 120명, 동시접속자 80명이 이용하는 서비스를 운영했습니다. ORM 조회 구조를 분석하고 BatchSize와 Fetch Join을 개선해 한 요청에서 발생하던 쿼리 수를 5,000개에서 6개로 줄였습니다. 측정 결과를 팀에 공유하고 코드리뷰로 변경 영향을 확인하며 성능 문제를 공동의 학습과 재사용 가능한 해결 방식으로 전환했습니다.

### 적용 역량/기술

**글자 수: 186자 / 300자 이내**

Java 11, Spring Boot, JPA, Hibernate, QueryDSL, MySQL, Jenkins를 적용했습니다. ORM의 객체 연관관계와 실제 SQL을 함께 추적하는 분석 역량, 변경 전후 쿼리 수를 비교하는 검증 습관, 코드리뷰에서 문제 원인과 해결 근거를 설명하고 동료의 피드백을 반영하는 협업 역량을 길렀습니다.

## 자기소개 1. 서로 다른 전문성을 가진 동료 또는 비전문가와 협업하여 공동의 목표를 달성한 경험과, 그 과정에서 얻은 교훈을 구체적으로 기술해 주세요. (300~600자)

**글자 수: 438자**

[재직 중 사내 고객경험 개선 프로젝트] 최소주문금액 안내 기능을 만들 때 7개 이상의 유관부서가 참여했습니다. 기획은 일정과 고객경험, 개발은 안정성, 일부 부서는 단기 매출효과를 중시해 우선순위 합의가 어려웠습니다. 저는 각자의 주장을 반복하기보다 고객이 주문 가능 여부와 부족 금액을 확인하려고 상품 화면과 장바구니를 오가는 행동을 공통 문제로 정의했습니다. 사용자 행동지표와 부서별 요구를 한 자료로 정리하고, 모든 요구를 한 번에 구현하지 않고 핵심 안내 기능부터 작게 출시해 검증하자고 제안했습니다. 백엔드 개발을 주도하며 상태와 예외조건을 함께 점검한 결과 장바구니 이탈 감소와 주문전환율 향상에 기여했고 전사 UX 성공사례로 공유됐습니다. 이 경험으로 협업은 상대를 설득하는 일이 아니라 서로 다른 제약을 공동의 사용자 문제와 검증 기준으로 연결하는 일임을 배웠습니다.

## 자기소개 2. 업무 수행 중 편법이나 단기적 성과에 타협하지 않고 원칙을 지켜낸 경험, 당시의 판단 기준, 그리고 이를 통해 형성된 본인만의 직업윤리를 구체적으로 기술해 주세요. (300~600자)

**글자 수: 474자**

[재직 중 사내 서버 분리 프로젝트] 92개 API, 10개 모듈, 약 400개 테이블과 DB·Redis를 신규 서버로 옮겼습니다. 일정만 맞추려면 일부 점검을 줄일 수도 있었지만, 운영 중인 상품과 기획전 데이터의 누락은 고객 불편과 조직의 신뢰 훼손으로 이어진다고 판단했습니다. 그래서 개발 완료가 아니라 영향범위·검증·기록·재발 방지까지 확인해야 일이 끝난다는 기준을 세웠습니다. 의존관계를 먼저 정리하고 전환 단위를 나눴으며, 변경 전후 데이터 흐름과 빌드 결과를 단계별로 확인했습니다. Batch·메시지 큐·JDBC·비동기 처리에는 MDC 기반 전역 로깅을 적용해 문제가 생기면 원인과 영향을 추적하도록 했습니다. 그 결과 상품·기획전 기능을 운영 중단 없이 전환했습니다. 이후 저는 빠른 완료보다 고객 영향을 기준으로 판단하고, 불확실성을 숨기지 않으며, 같은 조건의 검증 결과와 기록으로 책임을 설명하는 것을 직업윤리로 삼고 있습니다.

## 자기소개 3. 수많은 금융기관 중 NH농협은행에 지원하게 된 동기와, 지원 분야에서 발휘할 수 있는 본인만의 차별화된 강점을 구체적으로 기술해 주세요. (300~600자)

**글자 수: 448자**

NH농협은행이 생성형 AI를 기업심사와 금융상담에 적용하면서도 객관적이고 일관된 판단, 고령층과 외국인의 금융 접근성처럼 신뢰와 포용을 함께 추구한다는 점에 끌렸습니다. AI는 기술의 정확도만으로 완성되지 않고 현업의 판단 기준과 고객의 언어, 안정적인 운영까지 연결돼야 한다고 생각합니다. 저의 차별화된 강점은 언어·사용자 경험·기술 구조를 함께 보는 시각입니다. 학교교육에서 국문학·디자인·컴퓨터공학을 공부했고, 실무에서는 이용자 100만 명 이상인 커머스 플랫폼의 백엔드 시스템을 운영했습니다. 7개 이상 부서의 요구를 사용자 행동지표로 구조화해 핵심 기능을 출시했고, API 응답시간을 909ms에서 18ms로 줄였으며, 대규모 DB·Redis 이관을 운영 중단 없이 마쳤습니다. 이 경험으로 현업의 문제를 명확한 기준으로 바꾸고 고객이 이해할 수 있는 AI 서비스를 안정적으로 운영하겠습니다.

## 자기소개 4. 입행 후 지원 분야에서 추진하고 싶은 실무 과제나 목표를 제시하고, 본인의 전문지식과 기술을 어떻게 적용하여 성과를 창출할 것인지 구체적으로 기술해 주세요. (300~600자)

**글자 수: 467자**

입행 후에는 AI 서비스의 답변 품질과 운영 위험을 함께 관리하는 평가·모니터링 체계를 만들고 싶습니다. 먼저 상담과 심사 등 현업 업무를 익혀 정확성, 근거 제시, 개인정보 보호, 응답시간, 사람의 검토가 필요한 예외를 평가 기준으로 정의하겠습니다. 이후 실제 이용 과정의 질문과 오류를 유형화하고, 배포 전 대표 시나리오 평가와 배포 후 품질지표·로그 모니터링을 연결하겠습니다. 저는 TPS 1,000 환경에서 로그와 지표로 병목을 찾아 API 응답시간을 909ms에서 18ms로 줄였고, 분산된 처리 흐름에 MDC 기반 전역 로깅을 적용했습니다. 이 경험을 활용해 모델이나 데이터가 바뀔 때 같은 조건에서 품질을 비교하고 이상 징후의 원인을 빠르게 추적하겠습니다. 장기적으로는 고령층과 외국인을 포함한 고객이 이해하기 쉬우면서도 직원이 결과의 근거와 한계를 확인할 수 있는, 설명 가능하고 중단 없는 AI 서비스를 운영하겠습니다.
