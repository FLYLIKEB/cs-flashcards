- **근무기간:** 2023.01~2024.11

### 수행역할(담당업무) 상세내용 (277자/300자)

이용자 100만 명 이상 커머스 플랫폼에서 상품 카탈로그·기획전·구좌·할인·필터·탭 API와 운영 시스템을 개발했습니다. 신규 가게홈 서버 분리 시 92개 API, 10개 모듈, 약 400개 테이블의 의존관계를 정리하고 Spring 다중 데이터소스, API 마이그레이션, DB·Redis 이관과 단계별 배포 검증을 수행했습니다. 기획전 상품 예약과 시간대별 노출 순서·일정 자동화를 구현했습니다. 각 기능의 의존관계와 데이터 흐름, 서비스 영향도를 확인하고 전환 순서와 검증 기준을 정리했습니다.

### 주요성과 (285자/300자)

상품·기획전 기능과 데이터 연속성을 유지하며 운영 중단 없이 신규 서버로 전환했고, 분리된 구조와 배포 전 검증으로 변경 안정성과 추적성을 높였습니다. TPS 1,000 환경의 배너 API에서 BatchSize, DB 조회 순서와 캐싱을 개선해 응답시간을 909ms에서 18ms로 약 98% 단축했습니다. 예약·노출 자동화로 수작업과 시간 오류 가능성을 줄여 운영자가 예외 상황과 기획 품질 검수에 집중하게 했습니다. 대규모 이벤트 트래픽에 안정적으로 대응하고 화면 응답 경험과 운영 효율을 함께 개선했습니다.

### 적용 역량/기술 (285자/300자)

Java, Spring Boot, JPA, QueryDSL, MySQL, Redis, Spring 다중 데이터소스, API 마이그레이션, BatchSize, 캐싱, 쿼리·성능지표 분석, 고트래픽 대응, 데이터 무결성, 변경·리스크 관리, 배포 전 검증, 일정 기반 처리, 상품 예약, 시간대별 노출 정책, 예외조건 설계, 반복업무 자동화 역량을 활용했습니다. 로그와 지표로 병목을 좁히고 변경 전·후를 같은 조건으로 검증하는 데이터 기반 문제해결 방식을 적용했으며, 영향범위 분석과 서비스 운영도 병행했습니다.

- **근무기간:** 2023.01~2024.11

### 수행역할(담당업무) 상세내용 (287자/300자)

장애·성능 저하 원인을 빠르게 찾기 위해 SQL 진입점·슬로우 쿼리 탐지를 개선하고 Batch·SQS·JDBC·비동기 처리에 MDC 전역 로깅과 배포 전 점검 기준을 적용했습니다. 약 1,000개 클래스의 Deprecated 참조를 자동 탐지·목록화하고 Google Apps Script로 일괄 반영한 뒤 참조와 빌드를 검증했습니다. 팀별 JIRA·DML·DDL·백포팅 절차의 공통·예외을 구분해 Slack 앱과 연동 흐름으로 통합했습니다. 공통 요청은 자동화하고 팀별 예외은 분리해 처리 기준을 명확히 했습니다.

### 주요성과 (296자/300자)

슬로우 쿼리 관련 평균 원인 파악 시간을 25분에서 9분으로 단축하고 장애 원인·변경 영향·처리 경로를 일관된 로그로 확인하게 했습니다. 대량 참조 수정을 자동화해 누락·휴먼에러를 줄이고 담당자가 예외 검토에 집중하게 했습니다. Slack·JIRA·Google 스프레드시트·GitLab 연동으로 20여 개 팀과 100여 개 워크플로우의 통합 지원 기반을 마련했고, Jenkins에서 JIRA·Git 티켓 연결을 배포 전 검증해 일관성과 추적성을 높였습니다. 자동 멘션과 온콜 상태 표시도 제안해 지원 흐름의 가시성을 보완했습니다.

### 적용 역량/기술 (286자/300자)

Java, Spring Boot, SQL, MDC, Batch, SQS·메시지 큐, JDBC, 비동기 처리, 슬로우 쿼리 탐지, 전역 로깅, 관측 가능성, 장애 대응, 운영 표준화, Google Apps Script, 정적 참조 탐지, 대규모 일괄 수정·빌드 검증, Slack 워크플로우·앱, JIRA, Google 스프레드시트, GitLab, Jenkins, 예외 설계, 반복요청 자동화, 배포 전 검증 역량을 활용했습니다. 개인의 주의력에 의존하던 업무를 검증 가능한 절차와 자동화로 바꾸는 데 집중했습니다.

- **근무기간:** 2023.01~2024.11

### 수행역할(담당업무) 상세내용 (288자/300자)

고객이 최소주문금액과 부족 금액을 알기 어려워 상품 화면·장바구니를 반복 이동하는 문제를 사용자 행동지표로 구조화했습니다. 7개 이상 유관 조직의 일정·고객경험·안정성·사업 목표를 공통 자료로 조율하고, 핵심 쟁점과 판단 근거를 문서화했습니다. 주문 가능 여부와 부족 금액을 보여주는 핵심 기능의 백엔드 개발을 주도했습니다. 실무 개선 경험을 사내 기술 블로그와 발표로 공유하고 서버개발그룹 운영진으로 월간 밋업·저자 초청 행사를 기획·진행했습니다. 발표자와 참석자의 질문을 연결하고 학습 내용을 조직에 남겼습니다.

### 주요성과 (286자/300자)

모든 요구를 한번에 구현하지 않고 고객의 핵심 불편을 해결하는 기능부터 출시해 장바구니 이탈 감소와 주문전환율 향상에 기여했고 전사 UX 성공사례로 공유됐습니다. 서로 다른 이해관계자의 요구를 사용자 행동과 공통 지표로 바꾸어 합의를 이끌고 핵심 기능을 안정적으로 구현했습니다. 문제해결 경험을 문서·발표로 정리해 백엔드 개발자 200명 이상의 조직 지식으로 확장하고, 발표자와 참석자의 질문·피드백·학습이 지속되는 환경을 만드는 데 기여했습니다. 개인의 개선 경험을 반복 가능한 조직 학습 자산으로 남겼습니다.

### 적용 역량/기술 (277자/300자)

사용자 행동지표 분석, 요구사항 구조화, 이해관계자 조율, 백엔드 개발, 상태·예외조건 설계, 핵심 기능 우선 출시, 고객경험 개선, 기술 문서화, 사내 기술 블로그, 기술 발표, 행사 기획·진행, 질문·피드백 조율, 지식공유, 기술 커뮤니케이션, 조직 기여 역량을 활용했습니다. 기술 구현에 그치지 않고 사용자와 유관 조직의 언어를 연결하고 공통 기준으로 합의를 만든 뒤 구현 결과를 문서와 발표로 환류했습니다. 상대의 제약과 일정·안정성·고객가치를 함께 고려하는 의사결정 역량도 발휘했습니다.

- 회사명 기재가 가능한 블라인드 채용인지 확인
